## The three things the new direction needs first

In the order I would do them.

### 1. The run manifest (the load-bearing gap)

**Nothing in this codebase represents "a run" as data.** Everything is either
fixed (the `characters` table, the single level) or calls global `randi_range()`
per site. The only seeded RNG in the project is `descent.gd:158` —
`_rng.seed = 20260808`, hardcoded, for the starfield.

Add: one integer seed → origin, race, region, modifiers, derived
deterministically. Everything downstream reads the manifest instead of rolling
locally.

This is not just a feature. **Procedural generation on global `randi()` is
untestable** — you cannot write a negative control against it. Seeded, it is
trivially provable: same seed, same run. The seed is what keeps this project's
measure-don't-assume discipline alive through a procedural pivot.

### 2. Wire the arrival text to the manifest

`scripts/intro.gd` already derives **every** beat of the cinematic from how long
the text takes to type — that is documented in the file and was verified when
the Alexander line was lengthened. So a rolled origin line reflows the whole
sequence for free. This is where a player first *feels* the new direction, and it
is nearly free.

### 3. Death fragments

A pool of lines unlocked by dying, keyed to how you died and what you had done.
A JSON table plus one death-screen line. Days, not months, and it is the piece
that makes the lore earned rather than dumped.

## Race and tower design

Capture format and a worked Corporate example: **`docs/RACE_BRIEF.md`**.

The measurement that drives it: every tower currently reaches **5.1–9.6 tiles**.
They differ by stats and nothing else visible. Identity must come from shape,
reach (in tiles — grid is 32px) and cadence.

What the engine can already express — cone with tunable angle (`flamethrower`),
chain (`tesla`), pierce (`arrow`), radius splash and ground pools (`cannon`),
ally spawning (`shrine`), unit tint (`ally.gd`). What is missing — tile-relative
range, a spawned unit that flies a pattern rather than chasing, a timed map-wide
sweep, and any reach under 5 tiles.

Of the three Corporate towers sketched: **tentacle is buildable today**, **flame
jet is a re-tune** of the existing cone, **airport is the only new system**.

Still needed for Corporate: what they are **bad** at (without it a race is a
reskin), their palette / FX vocabulary / music register, and death fragments.

## Open decisions that are the user's, not mine

1. **The glow blowout.** `_setup_world_environment` (main.gd ~3110) sets
   `use_hdr_2d = true` with `glow_blend_mode = GLOW_BLEND_MODE_ADDITIVE` — the
   only glow mode with no ceiling — against **17** `BLEND_MODE_ADD` emitters. A
   late fort sums past 1.0 without limit and the whole frame goes flat, bare
   ground included. `84902cf` bounded the largest single contributor (hellfire);
   a death screenshot washed *green* rather than orange proves it was one of
   several. Candidate fix `ADDITIVE` → `SCREEN`. **Do not flip it unmeasured** —
   that is precisely the mistake `3e01c17` was written about. Note `bloom` is
   already 0.0 and `hdr_threshold` 1.0 and both are intentionally not
   tier-dependent; that is a different bug and it is already fixed. Live
   mitigation for the user: Settings → Quality → Medium.
2. **Riding the Rainbow Coco.** Asked for, explicitly deferred rather than
   half-built — it touches player movement, camera, collision, attacking while
   mounted, death while mounted and build mode.
3. **The upgrade economics.** `structures.json` tower tier costs are dead data:
   all five towers override `get_upgrade_cost()` to a flat 500 gold + 1 essence
   and never read `tiers[N].cost`. At the real price, upgrading is **~9× less
   gold-efficient than building wide** (arrow DPS/gold 0.400 → 0.042 → 0.048;
   500 gold buys 25 more tier-1 arrows at +200 DPS, or one upgrade at +13.9).
   This is the same problem as solid-packing beating a deliberate maze.
4. **`quick_actions.gd`** — dead file, never instantiated. Wire it up or delete it.
5. **Shipping blockers, all needing information only the user has:** Apple
   Developer ID + team ID for macOS signing; a real Steam App ID
   (`steam_appid.txt` is still Valve's Spacewar `480`); `company_name` in
   `export_presets.cfg` is the placeholder `"cmo333"`.

## Traps this codebase has actually sprung

The PR body carries 41 numbered lessons. The ones most likely to bite next:

- **A data table is not the truth.** `structures.json` understates real tower
  damage; the code applies an essence-infusion multiplier on top, and measuring
  damage that *lands* moved it again. A balance pass tuned off the sheet had to
  be reverted in full. Read the value the game ends up with, on an enemy.
- **A multiplier can reach nothing.** Twice a tower multiplier was added and was
  inert — five towers override `_fire_at`, and eight firing sites re-tested raw
  range. Anything global should be folded into `get_tower_damage_mult()` /
  `get_tower_rate_mult()`, which every path already routes through.
- **A test that re-implements the code agrees with itself forever.** Spawn the
  real object; do not model it.
- **A fixture that passes in both builds proves nothing.** Run every new harness
  against the *unfixed* file first.
- **`:=` off an untyped value fails in the engine but passes `gdparse`.** Only
  `tools/check_scripts.sh` (which greps the engine's own stderr) settles it.
- **`preload()` in a SceneTree script compiles before autoloads attach** — the
  scene caches with no script and the probe silently measures nothing. Use
  `load()` at frame 2.
- **The clamp downstream can eat your change.** A +10%/5min horde step measured
  as working and delivered almost nothing because `HORDE_CAP_HARD_LIMIT` was
  already binding.

## Performance note

`HORDE_CAP_HARD_LIMIT` is now **900** (was 680). The adaptive scaler trims FX,
particles and projectiles but **never enemy count**, so nothing downstream
rescues a cap set too high. Frame cost at 900 has never been measured on real
hardware — only enemy counts have. It is the first knob to pull back if frames
drop around the 10-minute mark.
